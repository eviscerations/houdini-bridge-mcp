# トラブルシューティング

生きたドキュメントです — ツールがテストされるにつれて成長します。各項目：**症状 → 原因 → 対処**。

## パス / 制限（confinement）

**作業ディレクトリ内にあるパスに対して「path outside working directory」が出る**
- （Rustの`canonicalize()`による）`\\?\`のWindows拡張長プレフィックスが、プレフィックスなしのルートと一致しません。エグゼキューターは制限をかける前にこのプレフィックスを正規化します。
- 制限のルートは`arm.json`の`working_dir`（GUIの**Apply**で設定）からライブで読み込まれ、その配下のサブディレクトリは辿れます。設定が読み取れない場合はarm時の値にフォールバックします。

**ハイトフィールドの構築時に`SyntaxError: (unicode error) 'unicodeescape'`が出る**
- サーバーが記述したPython SOP文字列にWindowsパス（`C:\Users\...`）が補間され、`\U`がユニコードエスケープとして読まれています。補間前にパスをフォワードスラッシュにしてください。

## ハイトフィールド

**`hou.InvalidSize: … must be the same as the number of voxels in the volume`**
- HeightField SOPの`sizex/sizey`は**ワールドサイズ（メートル）**であり、サンプル数ではありません。これらを`gridspacing = res_m`とともに`cols/rows`に設定すると`cols/res`個のボクセルが構築され、`res == 1`のときにのみ正しくなります。
- 対処：`sizex = cols * res_m`、`sizey = rows * res_m`。最近傍リサンプルのガードにより、`setAllVoxels`は残った±1のずれに対しても堅牢になります。

## GUI

**ウィンドウがただの白いボックスとして表示される**
- eframeが毎フレームの開始時にOSテーマを再適用し、（ライトモードのOS上で）作成クロージャで一度だけ行われたダークの`set_visuals`を上書きしています。
- 対処：`update()`の先頭でビジュアルを設定し、パネルに明示的なダークの`Frame`フィルを与えます。

## ライセンス

### 「FBX/glTF/Alembic export is only supported in Houdini Core/FX」

FBX、glTF、AlembicのROPエクスポーターは、Apprentice（Non-Commercial）では無効化されています。

対処：無償版では`export_geometry`（`.obj` / `.bgeo`）または`export_cache`（`.bgeo.sc`）を使用してください。FBX / glTF / Alembicのエクスポートには、Core、FX、またはIndieのライセンスが必要です。

## ノードパス & 入力

### ジオメトリオペレーションの適用時に「Invalid node type name」

SOPが期待される場所に*オブジェクト*パス（`/obj/foo`）を渡しました — SOPはオブジェクトネットワーク内には作成できません。

対処：SOPパス（`/obj/foo/<sop>`）を渡すか、ツールにオブジェクトのディスプレイSOPを自動解決させてください（最近のビルド）。`read_geo_stats`または返された`sop`パスを使って探します。

### 「setInput failed」 — 第2入力のオペレーションがオブジェクト間でエラーになる

第2入力のオペレーション（`boolean`、`merge`、`drape`、`copy_to_points`）は、2つのオペランドが異なるジオオブジェクトに存在するときに失敗します。Houdiniの SOPは*異なる*ジオオブジェクトから入力を取れません。

対処：両方のオペランドを同じジオに置くか、先に第2のジオをobject-mergeで取り込んでください。同一ジオのオペランドは動作します。

### 「Cannot create a node inside a locked asset」

入力ノードがロックされたLabs HDA内にあり、オペレーションがその中に構築しようとしました。

対処：ロックされていないSOP上で操作するか、アセットのロックを解除してください。

## ジオメトリオペレーション

### ツールが「成功」するのに0ポイント / 空のジオを返す

これは失敗ではなく、パラメーターのスケール不一致です：
- `despeckle` — クラウドの間隔に対して半径が小さすぎると、すべてのポイントを除去します。
- `mesh_pointcloud` — ポイント間隔より大きいボクセルサイズはサーフェスを生成しません。
- `ocean_foam` — ホワイトウォーター / アニメーションソースが必要です。静止フレームでは0を返します。

対処：半径 / ボクセルサイズをデータの実世界スケールに合わせてください。シミュレーション由来のツールではフレームを進めてください。

## レンダリング & エクスポート

### `setup_karma` / `bake_texture`が画像を生成しない

⚠️ これらはワイヤー接続のみ（WIRE-ONLY）です — グラフを構築するだけで、レンダリングもベイクもしません。

対処：レンダー / ベイクをHoudiniで（またはROP経由で）開始してください。`export_*`、`flipbook`、`snapshot`、`save_scene`はファイルを書き出します。

### `export_usd`が保存に失敗する

USDエクスポートには、エクスポート元となる有効なLOP（Solaris）ネットワークが必要です。それがなければ書き出すものがありません。

対処：USDをエクスポートする前に、LOPネットへの`loppath`を指定（または構築）してください。

### シーンが平坦に見える / ライトに目に見える効果がない

ビューポートはデフォルトでヘッドライトシェーディングになっているため、シーンのライト（ポイント / 太陽など）はジオメトリをシェーディングしません。

対処：ビューポートを高品質ライティングに切り替えるか、`setup_karma`をセットアップしてレンダリングしてください。

### AMD ProRender（「RPR」） — プラグインは読み込まれるが「Render Devices」ダイアログがエラーになる

オプションの`AMDProRender/`の`hdRpr`デリゲートは動作しています：MSVC **v143**ツールセットで再ビルドされ、
Houdiniはフルプラグインでクリーンに起動し、「RPR」は選択可能なHydraレンダラーであり、ネイティブのRPR
マテリアルVOP、LOPのrender-settings、RPR Material Libraryのすべてが読み込まれます。既知の唯一の欠落はRPR
メニューの**Render Devices**ダイアログで、これはまだUSD-25のPythonバインディングへの移植を必要とします。

対処：レンダリングには不要です — Render Devicesダイアログは便利機能であって、前提条件ではありません。Hydraレンダラーとして
「RPR」を選択し、通常どおりレンダリングしてください。

## ポイントクラウド & 地形スケール

### 重いハイトフィールド / シーンがビューポートを停止させる

⚠️ 表示 + フレームオール（全体表示）はGPU上で数億個のボクセルをテッセレートします。

対処：重いジオメトリは表示をオフに保ち、`viewport_optimize` + `mem`を使い、フレームオールの代わりに特定のノードを`frame_selected`してください。

## リファレンス

ツールの正確なパラメーター、ノードタイプ、あるいはHoudiniの挙動が不明なときは、以下が信頼できる
情報源です — すべてオフラインで、ネットワークは不要です：

- **`node_reference` MCPツール** — Houdini 21.0.671向けの、ライブでプローブされた信頼できるノード/パラメーター
  リファレンスで、チャットから直接クエリできます（`node`、`search`、`category`）。その中身に推測は一切なく、あらゆる
  パラメーター名はライブのノードから読み取られています。セッション内からパラメーター名やそのデフォルトを確認する
  最速の方法です。
- **パラメーターリファレンスのアーカイブ** — [`reference/NODE_REFERENCE.md`](../reference/NODE_REFERENCE.md)は
  `node_reference`ツールを裏付ける、人間が読める形式のアーカイブです（パラメーターごとにgrep可能な1行）。
  構造化された記録元は`reference/houdini_nodes.json`です。完全な型付きツールカタログは
  `reference/catalog.json`です。リファレンス全体を一度に検索したいときに使用してください。
- **ローカルのHoudiniヘルプサーバー** — 実行中のすべてのHoudiniは、完全なオフラインのノード/パラメーター
  ドキュメントを組み込みWebサーバー上の**`http://127.0.0.1:48626/`**（SideFXのデフォルトヘルプポート）で提供します。
  中央のランディングページは[`http://127.0.0.1:48626/help/central.html`](http://127.0.0.1:48626/help/central.html)です。
  これは実行中のHoudiniビルドそのものに対する完全なSideFXドキュメントであり — パラメーター名だけにとどまらない、
  ノードの挙動に関する真実の情報源（ground-truth）です。
